# SI Local AI Launcher v1.3 — API 연결 업데이트

이 ZIP 하나만 받으면 됩니다. **기존 v1.2 또는 v1.2.1 전체 패키지에 덮어쓰는 작은 업데이트**입니다. 빌드된 Windows x64 Release EXE가 포함되어 직원 PC에서 컴파일할 필요가 없습니다. 모델과 CPU/CUDA 실행기는 기존 파일을 사용합니다. 분할 다운로드·복구 파일·파일 합치기가 필요하지 않습니다.

## 적용: 세 단계

1. Launcher에서 서버를 중지한 뒤 앱을 완전히 종료합니다. 트레이에 남아 있다면 트레이 메뉴에서 종료하세요.
2. 이 ZIP의 **내용물 전체**를 기존 `SI.LocalAI.Launcher.exe`가 있는 폴더에 풀고 같은 파일은 덮어씁니다. 압축 파일 안에서 바로 실행하지 마세요.
3. 기존 폴더의 EXE를 실행합니다. 앱 화면과 창 제목에는 버전을 표시하지 않습니다. 내부 버전은 EXE 속성과 `release-version.txt`에서 확인할 수 있습니다.

`offline-assets`, `state/settings.json` 및 개인 키는 이 ZIP에 포함하지 않습니다. 기존 모델·실행기·설정은 그대로 사용합니다. 이 업데이트만 빈 폴더에 풀면 실행기와 모델이 없으므로 서버를 시작할 수 없습니다.

## API 키로 연결하기

로컬 모델은 대화창과 OpenAI 호환 API로 모두 사용할 수 있습니다. 별도 LM Studio가 필요하지 않습니다.

1. **모델 라이브러리**에서 사용할 모델과 사고 모드 **OFF / ON**을 선택합니다.
2. **API 연결** 탭에서 **로컬 API 키 사용**을 켭니다. 기존 클라이언트 호환을 위해 처음에는 꺼져 있습니다.
3. **저장하고 서버에 적용**을 누릅니다. 최초 적용 시 로컬 전용 키를 생성하고 이후에는 같은 키를 유지합니다.
4. 준비 완료 후 **기본 주소 / 모델 ID / API 키**를 복사해 클라이언트에 넣습니다. 주소 기본값은 `http://127.0.0.1:1234/v1`입니다. 포트를 변경했다면 화면의 실제 주소를 쓰세요.

키는 이 PC의 llama-server에 접근하기 위한 키입니다. 사내 OpenCode 서버의 기존 키를 가져올 필요가 없습니다. 같은 PC에서 사용하며 사내망 공개 주소나 방화벽 설정을 자동 변경하지 않습니다. SI코파일럿은 별도 Visual Studio VSIX이므로 해당 확장이 제공하는 연결 설정을 사용합니다.

## OpenCode에서 쓰기

1. 서버가 준비된 상태에서 **OpenCode 설정 내보내기**를 누릅니다.
2. 새 프로젝트는 내보낸 JSON을 프로젝트의 `opencode.json`으로 사용합니다. 기존 `opencode.json` / `opencode.jsonc`가 있으면 `provider.si-local`을 병합하고 모델을 선택합니다. 기존 사내 설정을 통째로 덮어쓰지 마세요.
3. 키를 사용한다면 OpenCode에서 `/connect` → **Other** → 제공자 ID **si-local** → 앱에서 복사한 로컬 키를 입력합니다. 내보낸 JSON에는 실제 키가 없습니다.
4. OpenCode를 다시 열고 `/models`에서 **SI Local AI** 모델을 선택합니다.

문맥 길이 오류가 나면 API 연결 탭의 **문맥을 16K로 설정** → **저장하고 서버에 적용**을 사용할 수 있습니다. 메모리 사용량이 늘어나며 PC 성능에 따라 더 큰 모델은 실행되지 않을 수 있습니다. 모델·포트·문맥을 바꿨다면 실행 후 설정 파일을 다시 내보냅니다.

사내 배포 OpenCode에서 사용자 제공자를 허용하고 OpenAI 호환 제공자 패키지를 사용할 수 있어야 합니다. 이 업데이트는 OpenCode 설치·패키지 다운로드를 수행하지 않습니다. 사내 수정 버전과 실제 연동은 미검증입니다. API 연결 가능 여부와 코딩 도구 호출 품질은 별개이며 4B 모델의 복잡한 코드 작업 성능은 보장하지 않습니다.

## 사고 모드

- **OFF**: 지원 템플릿에서 생각 단계를 끄는 서버 기본값을 전달합니다.
- **ON**: 생각 단계를 켜는 서버 기본값을 명시적으로 전달합니다. 응답 시간과 출력 토큰 사용량이 늘어날 수 있습니다.
- 선택 후 시작 또는 재시작해야 반영됩니다. 실행 중 정보와 다음 적용 설정을 나누어 표시합니다.
- 제공된 llama.cpp b11429에는 `--reasoning on/off`를 사용합니다. 구형 실행기는 지원되는 경우 `--chat-template-kwargs`를 사용합니다. 둘 다 없으면 화면과 로그에 미지원으로 표시합니다.
- 모델의 템플릿이 지원해야 하며, 클라이언트의 요청별 옵션이 서버 기본값을 바꿀 수 있습니다. `--reasoning-format none`을 사고 OFF로 잘못 취급하지 않습니다.
- 짧은 연결 검사는 그 요청만 OFF로 실행합니다. 이 검사의 성공은 사고 ON의 실제 출력 검증을 뜻하지 않습니다.

## 키 보관과 적용

로컬 키는 실제 상태 폴더의 `local-api-key.txt`에 저장됩니다. 상태 폴더는 보통 EXE 옆 `state`이며 쓰기 불가능한 경우 사용자 AppData를 사용합니다. **진단 로그 → 로그 폴더 열기**로 실제 위치를 확인할 수 있습니다. 개인 키를 포함한 상태 폴더를 다른 직원에게 배포하지 마세요.

명령줄에는 키 값 대신 파일 경로를 전달하며 Launcher 로그와 `connection.json`, 내보낸 OpenCode JSON에는 실제 키를 기록하지 않습니다. 인증을 켰을 때 지원하지 않는 실행기로 인증 없이 실행하지 않습니다. 시작 단계에서 키 없음·틀린 키에 대한 401 거부와 정상 키의 모델 목록/생성 응답을 확인합니다. 이 검사는 직원 PC에서 실제 서버를 시작할 때 수행됩니다.

## 완료와 미검증

| 항목 | 이번 작업 결과 |
|---|---|
| 다운로드 | 기존 모델·CPU·CUDA 파일 재다운로드 없음. v1.2 자산과 출처·라이선스·해시 기록 유지 |
